STATEMENT: The CSCI shall read the aircraft TOML file at startup and shall not write it. The kinematic state, the phase, the phrase log, and the decision log shall exist only in memory and shall be discarded when the process stops. Acceptance is a loaded example file that the running aircraft does not modify, and a decision log that is an attribute of the aircraft object.
 RATIONALE: There is no operational database. The database description records that fact.

STATEMENT: The configuration file shall contain exactly the tables aircraft, performance, airport, runway, ramp, and option. aircraft shall carry n_number, facility, next_facility, and next_frequency_mhz in the range 118.000 to 136.975. performance shall carry taxi, rotation, and pattern speeds in increasing order, pattern altitude, takeoff and landing distances, turn rate, acceleration, vertical speed, and a low-approach height below pattern altitude. runway shall carry an identifier from 01 through 36 with optional L, C, or R, a heading from 0 through 359, length, left or right pattern, hold-short distance, pattern offset, and an upwind distance beyond the departure end. option.choice shall be full_stop, touch_and_go, stop_and_go, or low_approach. Extra keys and missing keys shall be errors. Acceptance is config/n123ab.toml loading and an empty file, a bad pattern, and a frequency of 100.0 being rejected.
 RATIONALE: One closed schema keeps a misspelled key from looking like a valid aircraft.
 ASSUMPTIONS: The Aircraft CSCI is a simulation. It is not connected to a real aircraft or a live facility, and this record does not claim certification authority approval.

 RATIONALE: A bad file is not a flyable aircraft.
