      1. Lifecycle, DID set, DAL E, Python, deferred transport, and trace rules AC-SDP001 The Aircraft CSCI software development plan shall record lifecycle data with the Software development plan (SDP), Software installation plan (SIP), Software transition plan (STrP), Operational concept description (OCD), System/subsystem specification (SSS), Software requirements specification (SRS), Interface requirements specification (IRS), System/subsystem design description (SSDD), Software design description (SDD), Database design description (DBDD), Interface design description (IDD), Software test plan (STP), Software test description (STD), Software test report (STR), Software user manual (SUM), Software product specification (SPS), and Software version description (SVD). Every aircraft requirement shall be DAL E. The implementation language shall be Python. The method that carries phraseology to the tower shall remain unselected. Each fragment shall name its parents, and each implementing source file shall name the requirement UID in a comment and in the commit that adds it. Acceptance is this record, with no claim of certification authority approval.
    AC-OCD003
    1. The spoken position matches the point-mass state AC-OCD003 When the pilot reports a position or includes a position in a call, the words shall describe the aircraft point-mass state at that moment, including the pattern leg when the aircraft is on one and the distance and direction when it is not. Acceptance is a concept in which a reader of the phrase log can tell the leg or the distance that the model occupied when the phrase was sent.
